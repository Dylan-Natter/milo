# Contributing

## Workflow

1. Link work to a GitHub Issue.
2. Use Spec Kit flow for non-trivial work:
   - `/speckit-specify`
   - `/speckit-plan`
   - `/speckit-tasks`
3. Implement on a short-lived branch.
4. Open PR using the repository PR template.
5. Provide deterministic validation evidence.

## Branching

- `main` is the canonical releasable branch.
- Use trunk-based development with short-lived branches.
- Do not create permanent `develop`-style branches.

## Validation

Run the bootstrap governance checks before requesting review.
